# AI-PROMPTS.md —— 给 AI 的 Prompt 模板（加词用）

> 以后碰到新词：把 Prompt + 词发给任意 AI → AI 返回 JSON → 粘贴进 `src/data/words.json` → `npm run check:data` → 部署。
> 本模板建立在你自己那份「10 节分析」Prompt 之上：**分析结构不变，只是把输出格式从散文改成 JSON**，好直接入库。

---

## 0. 工作流速览

```
你：  [完整 Prompt] + 一个词（如「見落とす」）
AI：  → 返回 JSON（code block）
你：  → 粘贴进 src/data/words.json 的 words 对象
     → npm run check:data        （不过就按报错改）
     → git push                  （Vercel 自动重新部署）
```

想要「先快速占位、以后补标本」→ 用**快速 Prompt**（第 2 节）；遇到全新的系 → 用**新系 Prompt**（第 3 节）。

## 1. 完整 Prompt —— 生成「収蔵済 标本卡」（推荐）

### 使用说明

- 粘贴下方整段 Prompt，在末尾 `<词面>` 处替换成你要的词，例如「見落とす」「取り込む」。
- AI 应返回**一个 JSON 代码块**。把它原样拷进 `words.json`（key 用 JSON 里的 `id`）。
- 如果 AI 给的字段不合规（缺必填、stars 越界、cls 不在 ①–⑤），跑 `check:data` 会告诉你哪里错，让 AI 修即可。

### Prompt 正文

````markdown
你是日语复合动词图鉴《複合動詞図鑑》的编辑助手。这个图鉴用「前項 × 後項」的组合地图来组织词：每个复合动词 = 一个前项系（如 取り〜）与一个后项系（如 〜込む）的交点。

现在给你一个词，请按下面的「构词分类」和「字段说明」分析它，并**只输出一个 JSON 代码块**（不要输出其他文字），字段必须严格符合 schema。

【构词分类 ①–⑤】（决定 cls 字段）
① 前項が後項を修飾 —— 前项修饰后项，词义 ≈ 前项方式 + 后项动作（例：押し出す「推着拿出」）
② 後項が前項を修飾 ／ 意味特殊化 —— 后项主导方向，或整体语义固定化、比喻化（例：振り当てる「分配」、出し惜しみ「该拿出却舍不得」）
③ 前項の接頭辞化 —— 前项虚化成前缀，基本不贡献词义（例：打ち明ける「坦白」，打ち 无实义）
④ 後項の接尾辞化 —— 后项虚化成后缀，转表状态/程度（例：考え込む「深思」，込む → 深入·沉浸）
⑤ 前後項の融合 —— 前后项融成整体，不能拆开解释，需整体记忆（例：落ち着く「沉着·安定」）

【可导出性 stars 1–5】从前项+后项的字面能否推出词义的程度：
★5 完全可推导；★3 大致可猜但有转折（如后项「惜しむ」由「珍惜」转「不肯给」）；★1–2 几乎不可推导，需整体记忆（如融合词）。

【JSON schema】（collected 形态）
{
  "id": "<罗马字 slug，小写连字符，如 miorosu>",
  "word": "<词面>",
  "reading": "<全假名读音>",
  "romaji": "<罗马字，如 mi-orosu>",
  "row": "<前项系 id（见下方系列清单；融合词为 null）>",
  "col": "<后项系 id（见下方系列清单；融合词为 null）>",
  "status": "collected",
  "series": "<归属系：取 row 或 col 的 id；融合词为 yugo>",
  "no": "<两位序号，如 05>",
  "seal": "<朱印一字，取自核心词义>",
  "stars": <1–5 整数>,
  "cls": "①|②|③|④|⑤",
  "clsNote": "<日文分类说明，如 前項が後項を修飾>",
  "genus": "<属，格式：系名 · 分支，如 取り〜系 · 获取>",
  "pos": "<品詞，如 五段動詞 / 名詞（…連用形）>",
  "tagline": "<一句话展示语，中文，可含 <b> 强调>",
  "core": "<核心イメージ，中日文混排，可含 <b>>",
  "eq": {
    "front": "<前项词形>", "frontSrc": "〈<前项原型动词>〉", "frontNote": "<前项含义，中文>",
    "back": "<后项词形>", "backRole": "<后项角色，如 後項 或 後項 · 接尾辞>", "backNote": "<后项含义，中文>",
    "backShift": "<可选：后项语义转换说明，格式：<b>意味転換</b> 「原义」→「转义」，可含 <b>>",
    "result": "<合成词>", "resultNote": "<合成词整体含义，中文>",
    "resultShift": "<可选：合成词语义分岔，如「① 复查 ② 让人刮目相看」>"
  },
  "families": [
    {
      "title": "<组标题，如 同後項「〜込む」· 深陷内心系>",
      "sub": "<组副标，中文>",
      "items": [["<近缘词1>", "<中文释义>"], ["<近缘词2>", "<中文释义>"], ["<本词>", "<中文释义>", true]]
    }
  ],
  "intersect": "<交叉点解说：本词在哪些家族的交叉点上，中文，可含 <b>>",
  "usages": {
    "biz": [["<日文商务例句1>", "<中文翻译>"], ["<日文商务例句2>", "<中文翻译>"], ["<日文商务例句3>", "<中文翻译>"]],
    "it": [["<日文 IT 例句1>", "<中文翻译>"], ["<日文 IT 例句2>", "<中文翻译>"], ["<日文 IT 例句3>", "<中文翻译>"]]
  },
  "note": "<覚え方 · 瞬间口诀，一句话，中文或带日文>",
  "noteZh": "<中文记忆说明，1–2 句>"
}

【系列清单】（row 填前项系 id，col 填后项系 id；不在清单里就说明「无对应系」，勿编造 id）
前项系 id：tori(取り〜) dashi(出し〜) kangae(考え〜) mi(見〜) oshi(押し〜) furi(振り〜) uchi(打ち〜) sashi(差し〜)
tachi(立ち〜) mochi(持ち〜) hiki(引き〜) omoi(思い〜) ii(言い〜) tobi(飛び〜) tsukai(使い〜) tabe(食べ〜)
yomi(読み〜) kaki(書き〜) hanashi(話し〜) aruki(歩き〜) hashiri(走り〜) nomi(飲み〜) kai(買い〜)
后项系 id：dasu(〜出す) komu(〜込む) kaesu(〜返す) modosu(〜戻す) kesu(〜消す) ageru(〜上げる) ireru(〜入れる)
nuku(〜抜く) shiburu(〜渋る) oshimu(〜惜しむ) kakeru(〜掛ける) ateru(〜当てる) katsu(〜勝つ) akeru(〜明ける)
osaeru(〜押さえる) nozoku(〜除く) atsukau(〜扱う) matomeru(〜まとめる) naosu(〜直す)
sugiru(〜過ぎる) au(〜合う) kiru(〜切る) toru(〜取る) hajimeru(〜始める) tsuzukeru(〜続ける) owaru(〜終わる)
mawaru(〜回る) nokosu(〜残す) awaseru(〜合わせる) ukeru(〜受ける) kaeru(〜返る) kumu(〜組む)

【生成要求】
1. 分析顺序请覆盖你之前习惯的 10 个方面：基本意义、前项、后项、核心イメージ、构词分类、可导出性、同后项词、同前项词、商务例句×3、IT例句×3——它们分别落入上面的字段。
2. 近缘词（families）只写**真实存在、且确实是同前项或同后项的复合动词**；不确定就少写，绝不编造。
3. reading 用平假名；例文要自然、符合场景（商务 ≈ 职场/会议/报告，IT ≈ 开发/系统/数据）。
4. 第 ⑤ 类融合词：row 和 col 都填 null，series 填 yugo，stars 建议 ≤2，core 强调「整体记忆」。
5. 只输出 JSON 代码块，不要 Markdown 散文、不要解释、不要注释。

<词面>
````

### 你的 10 节分析 → JSON 字段 对照表

| 你原来的分析 | 对应字段 |
|---|---|
| 1 基本意義 | `tagline` + `noteZh` |
| 2 前項 | `eq.front` / `eq.frontSrc` / `eq.frontNote` |
| 3 後項 | `eq.back` / `eq.backRole` / `eq.backNote`（语义转换 → `eq.backShift`） |
| 4 核心イメージ | `core` |
| 5 構詞分類 | `cls` + `clsNote` |
| 6 可導出性 | `stars` |
| 7 同後項の語 | `families` 里「同後項」那组 |
| 8 同前項の語 | `families` 里「同前項」那组 |
| 9 ビジネス例文 | `usages.biz` |
| 10 IT例文 | `usages.it` |

（`seal` / `genus` / `pos` / `intersect` / `note` 是图鉴卡片额外需要的字段，Prompt 已要求。）

## 2. 快速 Prompt —— 生成「既知 占位卡」（先占位，后补标本）

### 使用说明

没时间做完整标本时用。返回精简 JSON（`status: "known"`），矩阵立刻亮一格淡格。

### Prompt 正文

````markdown
你是日语复合动词图鉴《複合動詞図鑑》的编辑助手。图鉴用「前項系 × 後項系」组合地图组织词。

请分析下面这个词，只输出一个 JSON 代码块（known 占位形态），不要其他文字：
{
  "id": "<罗马字 slug>",
  "word": "<词面>",
  "reading": "<全假名读音>",
  "row": "<前项系 id（见下）；不知或融合词填 null>",
  "col": "<后项系 id（见下）；不知或融合词填 null>",
  "status": "known",
  "series": "<归属系 id：row 或 col 的 id，融合词为 yugo；都不确定则省略>",
  "stars": <可选 1–5，不确定就省略>,
  "cls": "<可选 ①②③④⑤，不确定就省略>",
  "gloss": "<中文释义，1–4 个词>",
  "cat": "<分类标签：获取/処理/受容/心理系/商务/IT/構詞①…⑤/融合 等>",
  "note": "<備忘録，一句话：记忆点、易混词或为什么认识>"
}
构词分类：① 前项修饰后项 ② 后项修饰前项/意味特殊化 ③ 前项前缀化 ④ 后项后缀化 ⑤ 前后项融合。
已知的前项系 id：tori(取り〜) dashi(出し〜) kangae(考え〜) mi(見〜) oshi(押し〜) furi(振り〜) uchi(打ち〜) sashi(差し〜) tachi(立ち〜) mochi(持ち〜) hiki(引き〜) omoi(思い〜) ii(言い〜) tobi(飛び〜) tsukai(使い〜) tabe(食べ〜) yomi(読み〜) kaki(書き〜) hanashi(話し〜) aruki(歩き〜) hashiri(走り〜) nomi(飲み〜) kai(買い〜)
已知的后项系 id：dasu komu kaesu modosu kesu ageru ireru nuku shiburu oshimu kakeru ateru katsu akeru osaeru nozoku atsukau matomeru naosu sugiru au kiru toru hajimeru tsuzukeru owaru mawaru nokosu awaseru ukeru kaeru kumu
只输出 JSON 代码块。

<词面>
````

## 3. 新系 Prompt —— 遇到全新的前项/后项

遇到现有 `series.json` 里没有的系（比如遇到「流し〜」这种新前项）时用。

### Prompt 正文

````markdown
你是日语复合动词图鉴《複合動詞図鑑》的编辑助手。

下面是一个新的前项/后项系（做前缀或后缀的复合动词系）。请只输出一个 JSON 代码块，符合 src/data/series.json 里的一条 row 或 col：
{
  "id": "<罗马字 slug，如 nagashi>",
  "name": "<系名，如 流し〜（前项）或 〜流す（后项）>",
  "proto": "<原型动词>",
  "kan": "<语感说明，一句话中文，讲清这个系的核心意象>"
}
注意：是前项系就叫 xxx〜，是后项系就叫 〜xxx。只输出 JSON 代码块。

词/现象：<描述你遇到的词或现象>
````

加完系后，在 `src/data/series.json` 的 `rows`（前项）或 `cols`（后项）数组里加上这条记录。新系会自动获得通用系页（无需改代码）。

## 4. 入库模板（words.json 里要粘的样子）

```jsonc
{
  "words": {
    // …已有词条…
    "miorosu": { "id": "miorosu", "word": "見落とす", "reading": "みおとす", "status": "known", "row": "mi", "col": "otosu", "series": "mi", "stars": 2, "cls": "④", "gloss": "看漏 · 疏忽", "cat": "IT/商务", "note": "「看漏」——目光往下落，漏掉了。" }
  }
}
```

> 粘贴时注意：`words` 对象里 key 要与该词条的 `id` 字段完全一致；字段顺序无所谓；逗号别漏。

## 6. 常见问题

| 问题 | 处理 |
|---|---|
| AI 返回的不是 JSON，是散文 | 让它「重新输出：只输出一个 JSON 代码块」 |
| `check:data` 报字段缺失 | 把报错原文粘给 AI，让它补 |
| AI 编造近缘词 | 复述要求「近缘词只写真实存在的，不确定就少写」 |
| 词到底算 ① 还是 ③ | 看前项是否虚化：还能解释就 ①，几乎只剩强调/语气就是 ③ |
| 想一次加一批词 | 把多个词并列发给 AI，要求逐个输出 JSON（每个独立 code block），再逐个人工核对入库 |
